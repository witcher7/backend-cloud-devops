Think of Athena like “SQL on top of raw files”. So first you drop some fake logs into S3, then you query them like a database. Easy flex.

Let’s use JSON logs because they’re clean and Athena loves them.

Create a file called:

```
app-logs.json
```

Put this inside:

```json
{"timestamp":"2026-01-15T10:01:12Z","level":"INFO","service":"auth-service","user_id":"u101","action":"login","status":200,"latency_ms":120,"ip":"192.168.1.10"}
{"timestamp":"2026-01-15T10:02:45Z","level":"ERROR","service":"auth-service","user_id":"u102","action":"login","status":401,"latency_ms":80,"ip":"192.168.1.11"}
{"timestamp":"2026-01-15T10:03:22Z","level":"INFO","service":"payment-service","user_id":"u103","action":"payment","status":200,"latency_ms":350,"ip":"192.168.1.12"}
{"timestamp":"2026-01-15T10:04:10Z","level":"WARN","service":"payment-service","user_id":"u104","action":"payment","status":504,"latency_ms":900,"ip":"192.168.1.13"}
{"timestamp":"2026-01-15T10:05:01Z","level":"INFO","service":"order-service","user_id":"u105","action":"create_order","status":201,"latency_ms":200,"ip":"192.168.1.14"}
{"timestamp":"2026-01-15T10:06:30Z","level":"ERROR","service":"order-service","user_id":"u106","action":"create_order","status":500,"latency_ms":700,"ip":"192.168.1.15"}
```

Upload this file to:

```
s3://your-bucket-name/logs/app-logs.json
```

Now in Athena, create a table:

```sql
CREATE EXTERNAL TABLE app_logs (
  timestamp string,
  level string,
  service string,
  user_id string,
  action string,
  status int,
  latency_ms int,
  ip string
)
ROW FORMAT SERDE 'org.openx.data.jsonserde.JsonSerDe'
LOCATION 's3://your-bucket-name/logs/';
```

Run:

```sql
MSCK REPAIR TABLE app_logs;
```

Now the fun part. Sample queries that feel real-world:

1. See all logs

```sql
SELECT * FROM app_logs;
```

2. Find all errors

```sql
SELECT *
FROM app_logs
WHERE level = 'ERROR';
```

3. Count errors per service

```sql
SELECT service, COUNT(*) AS error_count
FROM app_logs
WHERE level = 'ERROR'
GROUP BY service;
```

4. Average latency per service

```sql
SELECT service, AVG(latency_ms) AS avg_latency
FROM app_logs
GROUP BY service;
```

5. Find slow requests (>500ms)

```sql
SELECT *
FROM app_logs
WHERE latency_ms > 500
ORDER BY latency_ms DESC;
```

6. Find failed HTTP statuses

```sql
SELECT *
FROM app_logs
WHERE status >= 400;
```

7. Requests per service

```sql
SELECT service, COUNT(*) AS total_requests
FROM app_logs
GROUP BY service;
```

8. Who is spamming errors

```sql
SELECT user_id, COUNT(*) AS failures
FROM app_logs
WHERE status >= 400
GROUP BY user_id
ORDER BY failures DESC;
```

9. Auth service login failures

```sql
SELECT *
FROM app_logs
WHERE service = 'auth-service'
  AND action = 'login'
  AND status != 200;
```

10. Timeline view (log-style)

```sql
SELECT timestamp, service, level, action, status, latency_ms
FROM app_logs
ORDER BY timestamp;
```

This is basically how real production log analysis looks, just at baby scale. Same patterns power:

* CloudWatch → S3 → Athena
* ALB logs → Athena
* Kubernetes logs → Athena
* Security audit logs → Athena
